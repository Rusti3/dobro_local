# Как разметка используется в приложении

Система разделяет **факты ДОБРО**, **смысловую разметку LLM** и **поведение пользователя**. Модель не переписывает адреса, даты, категории источника и ограничения, а добавляет признаки, которых нет в исходной выгрузке.

На текущий каталог из 56 событий наложена разметка 42 событий. Для 14 карточек, которых нет в новом снимке данных, остаётся старое безопасное поведение. Три размеченные карточки со статусами `hidden` или `human_review` не попадают в клиентскую выдачу.

## Три уровня использования

### 1. Безопасность выдачи

До ранжирования сервер применяет жёсткие правила:

- `hidden` и `human_review` не показываются;
- возраст проверяется по факту из ДОБРО;
- завершившиеся события исключаются кодом;
- `clarification_required` можно показать, но карточка получает заметку «Есть что уточнить», а экран дела — конкретный список вопросов организатору.

LLM не решает, истекло ли событие, является ли оно дублем и находится ли оно рядом. Эти проверки остаются детерминированному коду.

### 2. Порядок персональной ленты

Основой остаётся вектор предпочтений пользователя: темы, формат, социальность, характер активности, длительность и расстояние. Лайк, пропуск, добавление в план и завершённый визит обновляют этот вектор.

Поверх пользовательского совпадения применяется небольшой редакционный коэффициент:

- понятная карточка получает преимущество;
- высокий `firstTimeFit.score` поднимает событие;
- сложность до 39 немного поднимает событие;
- сложность от 60 немного опускает событие;
- случайная стабильная добавка только развязывает равные результаты и не меняется при перезагрузке.

Итоговый порядок не является просто сортировкой «от лёгкого к сложному»: сначала учитывается вкус человека, а сложность помогает выбрать более мягкий вариант среди похожих дел.

### 3. Объяснение пользователю

Разметка раскрывается постепенно, чтобы карточки не превратились в анкету:

- в ленте видны короткое смысловое описание, сложность, пригодность новичку и предупреждение об уточнениях;
- в свайпах показываются формат, возможность участвовать одному/вместе и уровень сложности;
- на странице дела видны баллы «Для первого раза» и «Сложность», плюсы, риски и вопросы координатору;
- в сворачиваемом блоке «Все условия дела» находятся конкретные задачи, семь осей сложности, допустимый способ участия, необходимые ресурсы и предварительные требования;
- если у события несколько вакансий, интерфейс сообщает, что выбрана наиболее подходящая роль, а не смешивает противоречивые условия разных вакансий.

## Фильтры

Быстрые фильтры используют только достаточно строгие признаки:

| Фильтр | Условие |
| --- | --- |
| Первый раз | качество `suitable` и вердикт новичку `suitable` |
| Попроще | нормализованная сложность `0–39` |
| Из дома | подтверждена конкретная удалённая задача и формат `online` |
| Спокойно | `calmTask=yes` |
| С друзьями | `friendsAllowed=yes`, а не просто массовое событие |
| Разово | обязательство `one_off` |

Расширенный фильтр «Кому помочь» строится по `beneficiaryGroups` и дополнительным направлениям. Поиск индексирует заголовок, описание, короткое объяснение и конкретные структурированные задачи ДОБРО.

Фильтры объединяются по правилу **И**: например, «Попроще» + «Животные» показывает только простые дела для животных. Пустой результат честно предлагает убрать один фильтр и не подмешивает неподходящие карточки.

## Подборки ленты

Подборки строятся из признаков, а не из похожих слов в тексте:

- **Хорошо для первого раза** — строгий `first_time`;
- **Рядом с тобой** — расстояние из координат;
- **На выходные** — конкретная дата действительно приходится на субботу/воскресенье;
- **Можно пойти с друзьями** — совместное участие явно подтверждено;
- **На час-два** — известная длительность не больше 120 минут;
- **Помочь из дома** — есть конкретная удалённая работа;
- **Похоже, тебе понравится** — максимальное совпадение с обученным профилем;
- **Попробовать что-то новое** — разнообразие за пределами уже просмотренных тем.

Длинная программа, начавшаяся в субботу, не попадает автоматически в «На выходные». Онлайн-категория без конкретной удалённой задачи не попадает автоматически в «Из дома».

## Какие поля куда идут

| Часть разметки | Использование |
| --- | --- |
| `quality` | жёсткий отсев, предупреждение, вопросы координатору |
| `causeAreas`, `beneficiaryGroups` | темы, аудитории, фильтрация |
| `volunteerTasks`, `structuredTasks` | поиск и блок конкретных обязанностей |
| `format`, `participation` | фильтры, свайп, карточка и экран дела |
| `complexity` | ранжирование, чип на карточке, подробная расшифровка |
| `firstTime` | подборка новичка, балл, плюсы и риски |
| `feedSignals` | строгие группы «из дома», «спокойно», «с друзьями» |
| `requirements` | «что понадобится», предварительные условия и список вопросов |
| `facts` | длительность, выходной, возраст и подтверждённые требования |

## Обновление данных

После новой разметки каталог обогащается командой:

```powershell
npm run catalog:enrich-annotations
```

Скрипт выбирает лучшую вакансию события по качеству, пригодности новичку и сложности, сохраняет количество альтернатив и добавляет компактный объект `annotation` в `data/catalog.json`. После обновления нужно запустить:

```powershell
npm test
npm run build
```

Полная схема ответа модели остаётся в `schemas/event-semantic-annotation.schema.json`; клиент получает только компактную проекцию, нужную для выдачи и объяснений.
